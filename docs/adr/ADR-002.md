# ADR-002: Repository as Knowledge

## Context

Tickets and chat are useful coordination surfaces but can be inaccessible, mutable, or detached
from the revision they influenced. Contributors and agents need durable context during offline and
historical review.

## Decision

Store canonical product, architecture, package, agent, and validation artifacts as reviewable text
in this repository. External systems may link to these artifacts but are not authoritative. Avoid
duplication by linking to the canonical glossary, handbook, and governing artifacts with relative
paths. Automated checks verify local links.

## Consequences

Intent evolves with code, is available at a commit, and uses ordinary review controls. Repository
size and review surface increase modestly, and maintainers must keep metadata and links current.
Sensitive data must never be used as context; reference an approved secure system instead.

## Alternatives considered

- **Wiki as authority:** easy browsing but weak revision coupling and offline access.
- **Issue tracker as authority:** good workflow state but unsuitable for durable architecture and templates.
