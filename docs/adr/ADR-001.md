# ADR-001: Architecture First

## Context

Implementation choices made before system constraints are understood create incompatible patterns,
speculative domain models, and expensive reversals. Rocky needs a predictable boundary between
product outcomes and delivery details.

## Decision

Record consequential, cross-cutting, or difficult-to-reverse architecture decisions before their
implementation package is accepted. An EPKG SPEC must cite applicable accepted ADRs and may not
silently override them. Reversible local choices remain within the EPKG and code review.

## Consequences

Review begins with constraints and trade-offs, producing clearer packages and less rework. Authors
incur a small documentation cost and must distinguish architecture from routine design. Urgent work
may draft decision and implementation together, but acceptance of the ADR precedes acceptance of
dependent implementation.

## Alternatives considered

- **Code first, document later:** faster initially, but loses rejected options and encourages retrofit rationale.
- **Central architecture board:** consistent but creates a bottleneck and removes decisions from the code's history.
