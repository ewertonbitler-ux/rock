# ADR-003: AI Provider Abstraction

## Context

Automation can accelerate delivery, but provider-specific prompts, model names, and APIs couple
engineering knowledge to volatile products. Different environments also require different tools
and assurance levels.

## Decision

Express agent roles through provider-neutral responsibilities, inputs, outputs, constraints, and
quality gates. Keep shared context in `.ai` and normative requirements in standard artifacts. Core
framework artifacts and bootstrap code must not import an AI SDK or assume a provider. Any future
adapter must implement an independently specified boundary in a separate EPKG.

## Consequences

Context is portable and human-readable, providers can be substituted, and adoption does not require
a hosted AI service. Provider features need explicit adapters later, and lowest-common-denominator
guidance may require role-specific extensions that remain non-normative.

## Alternatives considered

- **Standardize one provider:** simpler initially but creates lock-in and embeds volatile configuration.
- **Forbid assisted workflows:** avoids integration risk but loses useful, reviewable automation.
