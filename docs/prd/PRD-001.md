# PRD-001: Rocky Engineering Framework foundation

## Product outcome

Deliver the first usable version of the chartered artifact system in
[RKY-000](../charters/RKY-000.md). A maintainer or agent can start at the repository root, discover
the governing intent, prepare a consistent engineering package, and produce reviewable validation
evidence without relying on private context or a vendor-specific service.

## Users and needs

- **Maintainer:** govern scope, accept decisions, and evolve artifacts without conflicting copies.
- **Contributor:** understand constraints and validate a change with documented commands.
- **Reviewer:** trace a change to requirements and assess evidence efficiently.
- **Agent operator:** give an automation role the minimum sufficient, provider-neutral context.

## Requirements

| ID | Requirement | Acceptance evidence |
| --- | --- | --- |
| PRD-001-R1 | Root navigation exposes charter, definition, handbook, decisions, glossary, current EPKG, and agent context. | Relative-link validation passes. |
| PRD-001-R2 | Artifact types have canonical templates, identifiers, status metadata, and lifecycle rules. | Handbook and templates agree. |
| PRD-001-R3 | The first EPKG includes SPEC, PROMPT, REVIEW, and TESTS artifacts with traceability. | EPKG-0001 review checklist is complete. |
| PRD-001-R4 | Architecture-first, repository-knowledge, and provider-abstraction decisions are recorded. | ADR-001 through ADR-003 are accepted. |
| PRD-001-R5 | Python bootstrap exposes reproducible lint, type-check, test, and link-check commands. | `make check` passes in a development environment. |
| PRD-001-R6 | Agent guidance identifies roles, authority boundaries, and accessible context. | `.ai/context.md` and catalog review pass. |

## Non-functional requirements

Documentation is English, concise, reviewable as text, and usable offline after checkout. Metadata
uses stable IDs and semantic document versions. Validation must not require network access after
development dependencies are installed. Canonical content is linked, not copied.

## Out of scope

Product domain classes, hosted services, workflow orchestration, tool-vendor adapters, and runtime
AI integrations are deferred. Their introduction requires a separately approved requirement and
engineering package.

## Release decision

The foundation is releasable when all requirements above are evidenced in
[EPKG-0001](../../.specs/epkg/EPKG-0001/REVIEW.md), required checks pass, and a maintainer accepts
the review. Usage analytics and additional artifact automation remain future decisions.
